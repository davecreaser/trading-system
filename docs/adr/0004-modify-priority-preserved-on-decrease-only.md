# Modify preserves time priority only on quantity decrease

Real exchanges differ on what a Modify does to an order's time priority. The simplest implementation treats every Modify as cancel-then-add, always losing priority — easy to reason about, but not how real exchanges (including NASDAQ) actually behave, and would misrepresent price-time priority in the writeup. We chose the real-exchange convention instead: decreasing an order's quantity alone is treated as harmless to the rest of the queue and keeps its original time priority; increasing quantity or changing price is treated as a new commitment and loses priority, re-queuing at the back. This is not meaningfully harder to implement than always-loses-priority, and getting it right is a genuine, checkable piece of market-microstructure knowledge — the kind of detail worth being correct about given the project's whole purpose.
