# Replay drives the order book's own crossing logic, not ITCH's reported executions

ITCH's `Order Executed`/`Order Executed With Price` messages report exactly what NASDAQ's real matching engine decided — an authoritative record of every fill that actually happened. The Feed Parser could have trusted these directly: feed `Add Order` in without crossing, then apply `Order Executed` messages as direct instructions to reduce specific resting orders, bypassing the Order Book's own matching logic entirely. We rejected that. The reason the Order Book exists at all is so a strategy (Epic 3) can inject its own hypothetical orders into a replay of real historical activity and have them genuinely match against it — which is only possible if the Order Book's own crossing logic is what performs the matching, since NASDAQ's real matching engine never accounted for a strategy that didn't exist. Trusting ITCH's reports as authoritative would have sidelined the exact engine Epic 1 was built and tested for, and would not have supported Epic 3 at all. Instead, `Order Executed`/`Order Executed With Price` messages are used only for validation: comparing what the Order Book's own crossing logic actually produced against what NASDAQ's real matching engine reported, as a correctness check against ground truth.
